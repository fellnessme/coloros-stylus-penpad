# 02 · 笔键为什么收不到（以及怎么绕过）

## 症状

- 按笔上的按键，系统有反应（比如截图），但自己的 App 完全收不到
- 无障碍服务明明声明了 `canRequestFilterKeyEvents`，`onKeyEvent` 却从不回调

## 排查过程

### 第一步：确认按键到底有没有进系统

```bash
adb shell getevent -lt /dev/input/eventX
```

按键时能看到：

```
EV_MSC  MSC_SCAN  000c0600
EV_KEY  KEY_UNKNOWN  DOWN
```

`0x000c0600` 是 HID Consumer usage：

| usage | 含义 |
|---|---|
| `0x000c0600` | 单击 |
| `0x000c0601` | 双击 |
| `0x000c0602` | 三击 |
| `0x000c0604` | 长按 |

多数笔固件对**快速连按**才会报 0601/0602；慢按始终是 0600，所以要自己按时间去重。

### 第二步：给它一个 keycode

编辑 `/system/usr/keylayout/Vendor_<vid>_Product_<pid>.kl`：

```
key 240 STYLUS_BUTTON_PRIMARY
```

`240` 是 `MSC_SCAN` 低位的值。改完 `dumpsys input` 里就能看到 `KEYCODE_STYLUS_BUTTON_PRIMARY`。

> 文件名必须匹配**按键设备**的 vendor/product，不是笔的触摸设备。
> 两个设备 VID 相同、PID 不同，很容易改错。

### 第三步：验证无障碍服务能不能收到

拿音量键做对照实验：

```
I PenPadKey: onKeyEvent code=24 ...   ← 音量键能收到
（按笔键：什么都没有）
```

**结论：音量键能到无障碍服务，笔键到不了。**

## 根因

ColorOS 在 `PhoneWindowManager.interceptKeyBeforeQueueing()` 里就把手写笔按键消费掉了：

```
D KEYLOG_PhoneWindowManagerExtImpl: overrideInterceptKeyBeforeQueueing:KeyEvent {... KEYCODE_STYLUS_BUTTON_PRIMARY ...}
```

这一步发生在事件进入派发队列**之前**，所以：

- 普通 App 收不到
- 无障碍服务的按键过滤也收不到（它拿的是派发后的流）
- 只有直接读 `/dev/input` 才能拿到

## 绕过办法

### 方案 A：shell 读设备 + 广播（本项目采用）

```bash
# 找到按键节点
getevent -pl | grep -B1 "Consumer Control"

# 常驻监听
getevent -c 1 /dev/input/eventX   | 匹配 000c0600 → am broadcast
```

两个坑：

1. **不能** `getevent -lt | while read`：管道是块缓冲的，事件会卡在缓冲区里。
   必须用 `getevent -c 1`（每次读一条就退出），才能实时拿到。
2. **广播必须显式指定组件**：

   ```bash
   am broadcast -n com.example/.MyReceiver -a com.example.PENKEY --ei code 0
   ```

   隐式广播会被 Android 8+ 的后台限制静默丢弃。

### 方案 B：Shizuku 代跑（不用电脑）

Shizuku 以 shell 身份运行，可以替 App 启动上面的脚本。
本项目 `ShizukuShell.java` 里实现了最小客户端：

```java
Bundle b = resolver.call(Uri.parse("content://<manager>.shizuku"), "getBinder", null, null);
IBinder binder = b.getBinder("moe.shizuku.privileged.api.intent.extra.BINDER");
IShizukuService svc = IShizukuService.Stub.asInterface(binder);
svc.newProcess(new String[]{"sh", "/data/local/tmp/penkeyd.sh"}, null, null);
```

需要两个前置条件：

1. App 声明并申请 `<manager包>.permission.API_V23`
2. 声明 `<queries><package android:name="<manager包>"/></queries>`
   —— 少这个会报 `Unknown authority`（Android 11+ 包可见性）

### 方案 C：root

有 root 就能把脚本放进 `/data/adb/service.d/`，开机自动以 root 跑，一劳永逸。
比 Shizuku 简单可靠得多。

## 附带发现

系统自己也会广播笔键事件：

```
com.oplus.ipemanager.action.PENCIL_SINGLE_CLICK
com.oplus.ipemanager.action.PENCIL_DOUBLE_CLICK
```

如果 IPeManager 服务正常，理论上监听这两个广播就够了，不需要读设备。
但在笔功能被裁剪的机器上，这两个广播**不会发**（服务本身是坏的）。
